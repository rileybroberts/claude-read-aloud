A shell pipeline connects command output to input with the pipe operator, while a subshell creates an isolated child shell process.

Pipelines chain commands left to right where standard out becomes standard in. Each command runs in its own subprocess. They execute concurrently and share the same environment, but variable changes in one stage don't affect others because each runs separately, though all descend from the same parent. A subshell, created with parentheses or explicit bash dash c, spawns an entirely new shell instance. It inherits the parent's environment but operates independently. Variable assignments, directory changes, and other state modifications inside vanish when it exits because they never touched the parent's memory space.

The code shows two examples: a pipeline where grep passes matches to word count, and a subshell that changes directory and removes logs, then prints the working directory, which is still the original location. The table compares five aspects: pipelines connect standard out to standard in between commands using the pipe operator, all stages run concurrently, exit status is the last command or with pipe fail, and variables are unchanged because of separate processes. Subshells execute commands in an isolated child shell using parentheses or bash dash c, run independently then exit, return their own exit status to the parent, and variables are scoped to the subshell only.

There are three gotchas. First, pipeline variables disappear. Writing a while loop inside a pipeline leaves count empty afterward because the loop runs in a subprocess that can't modify the parent's variables. Use process substitution or a here string instead. Second, subshell exits are invisible. A subshell can call exit one without terminating your script, it only exits itself, and the parent continues unless you check the exit status. Third, set dash e behaves differently. In pipelines it's enabled, only the rightmost command's failure kills the script unless pipe fail is on. In subshells, set dash e applies independently: the subshell dies but the parent might not unless you propagate the exit code.
