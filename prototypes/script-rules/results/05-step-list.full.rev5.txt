Open a second terminal and start Claude Code with the prototype plugin. Run the fast variant first since that's the one the design is leaning toward. The command sets the max thinking tokens variable to zero.

Then, if you have the patience, run it one more time without that environment variable for just the first item to feel the thinking delay.

Ask something that produces a long Response with a code block, a table, and a list. Work through this checklist, jotting a line per item and pasting them back here so I can pull the measured timings from the log.

First, when the Response lands, type the read aloud command. Note how many seconds until speech starts. Does the Script sound like a person talking? How did it handle the code, table, and list? Was there any dead air between paragraphs?

Second, check the screen footprint. What shows while the fork runs and when it finishes: a tasks footer hint, a task row, a relayed reading started line? Is that acceptable as the one-line notice?

Third, stop mid-reading with the read aloud stop command. How does the blocked expansion render, plain line or error banner? Did speech stop within a second? Did anything land in the conversation?

Fourth, mid-reading, type the read aloud command again. Was there a clean handover to the new reading? Fifth, test the control verbs. Type read aloud status, read aloud auto on, and read aloud auto off. Note the rendering only.

Sixth, try the variants. Type read aloud brief on a long Response, then read aloud show to see a Script on screen.

Seventh, type the read aloud command the instant a Response lands. Did it read the new one or the previous one?

Eighth, exit Claude Code while speech plays. The expected result is that speech continues. Ninth, give your gut verdict. Would you leave this on? What would make you turn it off?
