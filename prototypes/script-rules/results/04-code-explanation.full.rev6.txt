A shell pipeline connects commands left to right using the pipe operator, while a subshell creates a new child shell process that runs in isolation.

Pipelines chain commands together where the output of one becomes the input of the next. Each command runs in its own subprocess, and they execute concurrently. They share the same environment, but changes to variables in one stage don't affect others because each runs in a separate process, though they all descend from the same parent shell.

A subshell, created with parentheses or the bash dash c flag, spawns an entirely new shell instance. It inherits the parent's environment but operates independently. Variable assignments, directory changes, and other state modifications inside a subshell vanish when it exits because they never touched the parent's memory space.

The table compares how pipelines and subshells work. Pipelines connect stdout to stdin between commands using the pipe operator, while subshells execute commands in an isolated child shell using parentheses or bash dash c. All pipeline stages run concurrently, but subshells run independently and then exit. For exit status, pipelines use the last command's status or pipefail, while subshells return their own exit status to the parent.

In both cases, variables remain unchanged or scoped appropriately because they run in separate processes. There are three gotchas to watch for. First, pipeline variables disappear: writing a command that pipes to a while loop that reads lines and increments a counter leaves the counter empty afterward because the while loop runs in a subprocess that can't modify the parent's variables. Use process substitution or a here-string instead.

Second, subshell exits are invisible: a subshell can call exit one without terminating your script. It only exits itself, and your parent shell continues unless you explicitly check the exit status afterward. Third, the set dash e flag behaves differently. In pipelines with set dash e, only the rightmost command's failure kills the script unless pipefail is enabled. In subshells, set dash e applies independently: the subshell dies but the parent might not unless you propagate the exit code.
