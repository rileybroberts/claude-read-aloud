A shell pipeline connects command outputs to inputs, while a subshell creates an isolated child process.

Pipelines chain commands left to right where the output of one becomes the input of the next, using the pipe operator. Each command runs in its own subprocess, but they execute at the same time and inherit from the same parent shell. Variable changes in one stage don't affect others because each runs separately, even though they all come from the same parent.

A subshell, created with parentheses or an explicit bash command, spawns a brand new shell instance. It inherits the parent's environment but operates completely independently. Variable assignments, directory changes, and other modifications inside a subshell disappear when it exits because they never changed the parent's memory.

The table compares the two. Pipelines connect stdout to stdin using the pipe operator, while subshells execute in an isolated child shell using parentheses or bash dash c. In pipelines all stages run concurrently; in subshells they run independently then exit. The exit status of a pipeline is from the last command unless pipefail is set, while a subshell returns its own exit status to the parent. In both cases, variables are unchanged because they run as separate processes.

There are three gotchas to watch. First, pipeline variables disappear. If you write a command that pipes to a while loop that counts lines, the count variable stays empty afterward because the loop runs in a subprocess that can't modify the parent's variables. Use process substitution or a here-string instead. Second, subshell exits are invisible. A subshell can call exit with a nonzero code, but that only exits the subshell itself; your parent shell continues unless you explicitly check the exit status afterward. Third, set dash e behaves differently. In pipelines with set dash e, only the rightmost command's failure kills the script unless pipefail is enabled. In subshells, set dash e applies independently, so the subshell dies but the parent might not unless you propagate the exit code.
