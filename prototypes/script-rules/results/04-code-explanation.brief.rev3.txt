A shell pipeline connects commands left to right through the pipe operator, while a subshell creates an isolated child shell that inherits but doesn't affect the parent's environment.

Pipelines chain commands where standard output becomes the input to the next stage. Each command runs in its own subprocess concurrently, so variable assignments in one stage don't persist to the next because each process is separate. A subshell, created with parentheses or an explicit bash command, spawns an entirely new shell instance that inherits the parent's environment but operates independently. Any changes to variables or directories inside the subshell vanish when it exits because they only exist in that child process's memory.

The three practical gotchas are: first, pipeline variables disappear because the while loop runs in a subprocess and can't modify the parent's variables, so you need process substitution or a here-string instead. Second, when a subshell calls exit, it only exits itself, not your parent script, unless you check the exit status afterward. And third, with set minus e enabled, pipelines only fail on the rightmost command unless you turn on pipefail, while in subshells, set minus e applies independently to that child process alone.
